# NewsRoom – система моніторингу новин та генерації контенту
Вебзастосунок для моніторингу новин, відбору релевантних матеріалів і генерації контенту з використанням технологій штучного інтелекту.

## Призначення проєкту

`NewsRoom` — це дипломний бакалаврський проєкт, у якому реалізовано систему для редакторської роботи з новинними матеріалами. Застосунок дає змогу:

- створювати теми моніторингу з ключовими словами та часовими обмеженнями;
- підключати джерела типу `Сайт` і `Telegram`;
- запускати моніторинг у фоновому режимі;
- збирати новини з сайтів і Telegram-каналів;
- перевіряти релевантність новин через `OpenAI API` або локальний fallback-механізм;
- переглядати, фільтрувати, схвалювати, видаляти та додавати новини в обране;
- кластеризувати новини за змістовою схожістю;
- генерувати матеріали на основі вибраних новин і шаблонів контенту;
- редагувати, експортувати та видаляти згенеровані матеріали;

Проєкт побудований на серверному підході: інтерфейс формується через `Django templates`, а дані зберігаються через `Django ORM` у базі `SQLite`.

## Основні можливості

### 1. Теми моніторингу

Для кожної теми моніторингу користувач задає:

- назву теми;
- ключові слова та фрази;
- часовий фільтр;
- конкретну дату або період за датами;
- набір джерел.

Моніторинг запускається у фоновому режимі, тому після старту користувач може продовжувати працювати в системі.

### 2. Джерела новин

Підтримуються два типи джерел:

- `Сайт`
- `Telegram`

Для сайтових джерел система може:

- напряму обробляти RSS-стрічки;
- автоматично знаходити RSS;
- шукати матеріали через `sitemap.xml`;
- у разі потреби збирати статті зі сторінок сайту через HTML-аналіз.

Для Telegram використовується публічне посилання на канал формату:

```text
https://t.me/channel_name
```

### 3. Перевірка релевантності

Після первинного локального відбору система перевіряє, наскільки матеріал відповідає темі моніторингу.

- Якщо `OpenAI API` доступний, використовується AI-перевірка релевантності.
- Якщо `OpenAI API` недоступний, система переходить на локальний fallback на основі ключових слів і теми.

### 4. Робота з новинами

У модулі новин реалізовано:

- перегляд списку зібраних новин;
- фільтрацію за статусом, темою та пошуковим запитом;
- сортування;
- позначення новин як обраних;
- ручне схвалення новин після локального або AI-відхилення;
- видалення новин.

### 5. Кластери

Новини можна групувати в тематичні кластери. Для цього застосовується алгоритм на основі `TF-IDF` та `cosine similarity`.

Користувач може:

- запускати кластеризацію;
- переглядати список кластерів;
- відкривати вміст конкретного кластера;
- видаляти кластер.

### 6. Генерація контенту

Користувач може:

- обрати новину;
- обрати шаблон контенту;
- задати бажану довжину матеріалу;
- додати власні інструкції;
- вказати власну назву;
- згенерувати матеріал через `OpenAI API`.

Важливо:

- генерація контенту є AI-функцією;
- якщо `OpenAI API` недоступний, матеріал не створюється, а користувач бачить повідомлення про помилку;

### 7. Згенеровані матеріали

Після генерації користувач може:

- переглядати список згенерованих матеріалів;
- відкривати детальну сторінку матеріалу;
- редагувати текст;
- експортувати матеріал у формат `DOCX`;
- видаляти матеріал.

### 8. Шаблони контенту

У застосунку є окремий модуль шаблонів, де можна:

- створювати шаблони;
- редагувати опис і prompt-інструкцію;
- додавати приклади текстів;
- архівувати, відновлювати та видаляти шаблони.

### 9. Налаштування користувача

У розділі налаштувань користувач може:

- редагувати профіль;
- змінювати пароль;
- задавати персональні параметри генерації;
- обирати модель `OpenAI`, яка використовується в системі.

## Структура проєкту

```text
project/
|-- config/                        # Глобальні налаштування Django-проєкту
|-- newsroom/                      # Основний застосунок
|   |-- management/commands/       # Команди для підготовки демо-даних
|   |-- migrations/                # Поточна стартова міграція Django
|   |-- services/                  # Сервіси моніторингу, кластеризації, генерації, експорту
|   |-- templatetags/              # Користувацькі template tags і фільтри
|   |-- views/                     # Окремі модулі сторінок: моніторинг, новини, джерела тощо
|   |-- forms.py                   # Django-форми
|   |-- models.py                  # ORM-моделі
|   |-- constants.py               # Константи інтерфейсу та навігації
|   |-- context_processors.py      # Контекстні дані для layout-шаблонів
|   |-- session_state.py           # Робота з персональними налаштуваннями користувача
|   |-- urls.py                    # URL-маршрути застосунку
|-- static/newsroom/css/           # CSS-стилі застосунку
|-- templates/newsroom/            # HTML-шаблони сторінок і include-компонентів
|-- manage.py                      # Точка запуску Django
|-- requirements.txt               # Python-залежності
|-- .env.example                   # Приклад змінних середовища
```

## Встановлення та запуск

### 1. Створення віртуального середовища

#### Windows PowerShell

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 2. Налаштування змінних середовища

Для коректної роботи застосунку необхідно створити файл `.env` та вказати такі параметри:

```env
DJANGO_SECRET_KEY=change-me
DJANGO_DEBUG=True
DJANGO_ALLOWED_HOSTS=127.0.0.1,localhost
OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=gpt-4.1-mini
OPENAI_TIMEOUT_SECONDS=30
```

### Обов'язкові параметри

- `DJANGO_SECRET_KEY` — секретний ключ Django.
- `OPENAI_API_KEY` — власний API-ключ OpenAI для роботи AI-функцій системи.
### Інші параметри

- `DJANGO_DEBUG` — режим налагодження Django.
- `DJANGO_ALLOWED_HOSTS` — дозволені хости.
- `OPENAI_MODEL` — модель OpenAI, яка використовується в системі.
- `OPENAI_TIMEOUT_SECONDS` — максимальний час очікування відповіді від OpenAI API.

### Важливо

Для роботи AI-функцій необхідно замінити значення `your_openai_api_key` на власний дійсний API-ключ OpenAI.

Якщо цього не зробити:

- генерація контенту через ШІ не працюватиме;
- AI-перевірка релевантності новин виконуватиметься через локальний fallback;
- інші модулі системи залишаться доступними.

### 3. Підготовка бази даних

```powershell
python manage.py migrate
```

### 4. Заповнення демонстраційними даними

```powershell
python manage.py seed_demo_data
```

Команда створює демо-акаунт:

- логін: `demo_editor`
- пароль: `demo12345`

Також команда додає:

- активні шаблони контенту;
- тестові джерела;
- теми моніторингу;
- базові персональні налаштування для демо-користувача.

### 5. Запуск локального сервера

```powershell
python manage.py runserver
```

Після запуску застосунок буде доступний за адресою:

```text
http://127.0.0.1:8000/
```

## Адмін-панель Django

За потреби можна створити суперкористувача:

```powershell
python manage.py createsuperuser
```

Після цього адмін-панель буде доступна за адресою:

```text
http://127.0.0.1:8000/admin/
```

## Основні сторінки системи

- `/` — інформаційна панель
- `/monitoring/` — теми моніторингу
- `/sources/` — джерела новин
- `/articles/` — зібрані новини
- `/clusters/` — кластери новин
- `/drafts/` — генерація контенту
- `/generated/` — список згенерованих матеріалів
- `/templates/` — шаблони контенту
- `/settings/` — налаштування користувача

## Особливості реалізації

- Кожен користувач працює лише зі своїми темами, джерелами, новинами, шаблонами й матеріалами.
- Моніторинг тем запускається у фоні через окремий потік і не блокує інтерфейс.
- Під час виконання теми її редагування блокується.
- Якщо для теми не вибрано конкретні активні джерела, система використовує всі активні джерела користувача.
- Якщо активних джерел немає, тема не запускається.
- Пошук у сторінках застосунку реалізовано як case-insensitive, зокрема і для кирилиці.
- Для стилізації генерації в prompt передаються до трьох прикладів шаблону, кожен довжиною до 2000 символів.
- За замовчуванням у системі доступні моделі `gpt-4.1-mini`, `gpt-4.1` і `gpt-4o-mini`.
